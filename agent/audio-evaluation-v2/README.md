# Audio evaluation v2 fixtures

These six public development/pilot cases are synthetic, not heldout or human recordings. Each JSON identifies its version, expected state, required ASR coverage and final spoken-content presence patterns. Date-bearing cases expire after19November2026; create a new version instead of silently changing a frozen fixture. Tool execution uses the evaluation server's declared clock.

The runner requires a separately provisioned evaluation agent and marked isolated inventory root. Its provision manifest has schema1, purpose `fil-audio-evaluation`, agent_id, absolute evaluation_root, the three named tool_ids, agent_snapshot_sha256 and per-name tool_snapshot_sha256. Compute hashes from `model_dump(exclude_none=True)` using `fil_shop.audio_evaluation.provider_digest(snapshot, 'agent'|'tool')`. Provider GET readbacks must match before a signed URL is obtained. Known live agent IDs are rejected. The provision manifest is trusted operator evidence, not an automatic proof of deployment isolation.

Generate with an explicit `--case` and fresh `--output` fixture directory. Run with the same case/output plus `--agent-id`, `--evaluation-root`, `--provision-manifest` and unique `--trial-id`. Repeated trials reuse verified WAV hashes but write separate immutable trial directories. No provider action is implied by these instructions; authorization and allowance checks belong to the coordinator.

`grade-audio` takes independently transcribed final-response audio evidence containing audio_sha256, text and transcriber_version. The hash must match BOTH the saved run and current `final-received.wav`. Earlier words from `agent-received.wav` cannot establish final acknowledgement. Response IDs establish explicit association when available; event IDs alone or timestamp association remain uncertain. Received audio is not physical playback or a wall-clock two-party recording.

Spoken pattern matches establish content presence only. For example, “hold not placed” contains positive-consent keywords but is not success: actual expected-state grading and independent consent/semantic review remain required. Zero final holds does not prove that no transient reservation attempt occurred; incomplete tool traces retain an uncertain action-history criterion. `audio_content_present_semantics_pending` is deliberately not a case pass.

A full farewell such as “have a nice day” is required for the closing content control; truncated phrases and substring matches do not pass. Missing ASR coverage, an interrupted final reply, provider failure or timeout cannot become completion just because the script sent its fixtures.

Runnable stimulus kinds are request, language_switch, user_interruption and goodbye. Short backchannel, sentence-pause and background-speech response policies are not implemented and those kinds are rejected, rather than being claimed covered. Split-ASR timing and interruption mechanics have deterministic local trace tests, which are separate from behavioral coverage of those acoustic situations. Browser WebRTC, audio devices, acoustic echo, human naturalness and live UI synchronization remain outside this harness.
